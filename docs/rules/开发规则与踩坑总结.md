# GalaxySim3D 开发规则与踩坑总结

> 版本: v1.0 | 日期: 2026-06-08 | 用途: 降低未来开发错误概率

---

## 1. 架构层规则（最高优先级，违反即引入严重缺陷）

### RULE-ARCH-001: 引擎层绝对禁止依赖渲染层

**错误示例**:
```typescript
// ❌ 错误: OrbitEngine.ts 中引入 Three.js
import * as THREE from 'three'; 
```

**正确做法**:
```typescript
// ✅ 正确: 引擎层只输出纯数学结果
export class OrbitEngine {
  static getHeliocentricPosition(id: string, days: number): {x: number; y: number; z: number} {
    // 纯数学计算，无 Three.js
  }
}
```

**后果**: 一旦引擎层引入 Three.js，单元测试必须在浏览器环境运行（需 jsdom/webgl），CI 成本飙升，且引擎无法独立复用。

**历史案例**: 早期 `OrbitEngine` 曾尝试直接返回 `THREE.Vector3`，导致 Node.js 环境下无法运行单元测试。

---

### RULE-ARCH-002: 严禁同层横向依赖

**错误示例**:
```typescript
// ❌ 错误: UniverseViewer 直接调用 StarrySkyViewer 的方法
// UniverseViewer.tsx
starrySkyViewerRef.current.updateSomething();
```

**正确做法**:
```typescript
// ✅ 正确: 通过 App.tsx 状态中转
// App.tsx 管理状态，分别传给两个 Viewer
```

**后果**: 同层依赖导致组件耦合，无法独立测试和复用，重构时牵一发动全身。

---

### RULE-ARCH-003: 状态必须集中管理，禁止分布式状态

**错误示例**:
```typescript
// ❌ 错误: 子组件维护与父组件同步的状态
function Child({ initialTime }) {
  const [time, setTime] = useState(initialTime); // 与父组件不同步！
}
```

**正确做法**:
```typescript
// ✅ 正确: 单一数据源
function App() {
  const [timeState, setTimeState] = useState({ currentTimestamp: Date.now() });
  return <Child timeState={timeState} onTimeChange={setTimeState} />;
}
```

**后果**: 分布式状态导致数据不一致（如 UniverseViewer 和 StarrySkyViewer 显示不同的时间）。

## 2. 天文计算规则

### RULE-ASTRO-001: 时间尺度必须严格区分

| 计算类型 | 必须使用的时间尺度 | 错误示例 |
|----------|-------------------|----------|
| 轨道位置（行星） | TDB 天数 | 使用 UTC 天数 |
| 轨道位置（月球） | TDB 天数 | 使用 UTC 天数 |
| 恒星时 | UT1 | 使用 UTC 或 TT |
| 自转角度 | UT1 | 使用 TT |
| 用户显示 | UTC | 使用 TT |

**历史案例**: 早期使用 UTC 计算 GMST，每天累积约 1 秒误差，导致地面观星时角基准偏移。

---

### RULE-ASTRO-002: 历元坐标必须做岁差修正

**错误示例**:
```typescript
// ❌ 错误: 直接使用 J2000.0 星表坐标
const starRa = star.ra; // J2000.0 坐标
const starDec = star.dec;
// 直接用于当前年份...
```

**正确做法**:
```typescript
// ✅ 正确: 岁差修正到当前历元
const yearsSinceJ2000 = days / 365.25;
const { ra, dec } = ObserverEngine.applyPrecession(star.ra, star.dec, yearsSinceJ2000);
```

**后果**: 未做岁差修正导致恒星位置系统性偏移（100 年约 1.4°），北极星等标志性恒星位置明显错误。

---

### RULE-ASTRO-005: 方位角基准必须统一

**天文惯例**: 从南点开始，向东计量（0°=南，90°=东，180°=北，270°=西）
**导航惯例**: 从北点开始，向东计量（0°=北，90°=东，180°=南，270°=西）

**项目约定**: 内部计算使用天文惯例（从南点），UI 显示使用导航惯例（从北点）。

**历史案例**: 计算使用南点基准，UI 标注使用北点基准，导致东/西方向标注完全相反。

---

## 3. 渲染规则

### RULE-RENDER-001: 严禁每帧创建新对象

**错误示例**:
```typescript
// ❌ 错误: 每帧 new Vector3
const sunWorldPos = new THREE.Vector3();
sunMesh.getWorldPosition(sunWorldPos);

// ❌ 错误: 每帧 new BufferGeometry
moonOrbitLine.geometry.dispose();
moonOrbitLine.geometry = new THREE.BufferGeometry().setFromPoints(points);
```

**正确做法**:
```typescript
// ✅ 正确: 模块级复用对象
const _vec3 = new THREE.Vector3(); // 模块级声明
sunMesh.getWorldPosition(_vec3);

// ✅ 正确: 复用 BufferGeometry
moonOrbitGeo.setFromPoints(points);
moonOrbitGeo.attributes.position.needsUpdate = true;
```

**后果**: 每帧创建对象导致 GC 频繁触发，产生微卡顿（尤其在 3600x 高流速下）。

---

### RULE-RENDER-002: 严禁双 WebGL 上下文

**错误示例**:
```typescript
// ❌ 错误: 两个 Viewer 各自创建 Renderer
// UniverseViewer.tsx
const renderer1 = new THREE.WebGLRenderer();
// StarrySkyViewer.tsx
const renderer2 = new THREE.WebGLRenderer();
```

**正确做法**:
```typescript
// ✅ 正确: App.tsx 创建共享 Renderer
const rendererRef = useRef<THREE.WebGLRenderer | null>(null);
useEffect(() => {
  rendererRef.current = new THREE.WebGLRenderer({ antialias: true });
}, []);

// 两个 Viewer 接收 renderer prop
<UniverseViewer renderer={rendererRef.current} />
<StarrySkyViewer renderer={rendererRef.current} />
```

**后果**: 双上下文导致 GPU 显存翻倍（~600MB），移动端直接崩溃（多数移动浏览器限制最多 8 个上下文）。

---

### RULE-RENDER-003: 高频计算必须缓存

**错误示例**:
```typescript
// ❌ 错误: 每帧重新计算所有行星位置
planetsConfig.forEach(config => {
  const pos = OrbitEngine.getHeliocentricPosition(config.id, days);
  // ...
});
```

**正确做法**:
```typescript
// ✅ 正确: 时间量化缓存
const quantizedDays = Math.floor(days * 100) / 100; // 14.4 分钟粒度
if (quantizedDays !== lastCalculatedDays) {
  planetsConfig.forEach(config => {
    cachedPositions[config.id] = OrbitEngine.getHeliocentricPosition(config.id, quantizedDays);
  });
  lastCalculatedDays = quantizedDays;
}
// 使用 cachedPositions
```

**后果**: 无缓存时 1x 流速下 CPU 每帧计算 9 个行星轨道，帧率下降 30%。

---

### RULE-RENDER-005: 纹理必须全局缓存

**错误示例**:
```typescript
// ❌ 错误: 每次调用都重新绘制 Canvas
function createProceduralTexture(id: string) {
  const canvas = document.createElement('canvas');
  canvas.width = 2048;
  canvas.height = 1024;
  // 绘制数百次 arc/gradient...
  return new THREE.CanvasTexture(canvas);
}
```

**正确做法**:
```typescript
// ✅ 正确: 全局缓存
const globalTextureCache = new Map<string, THREE.Texture>();

export function createProceduralTexture(id: string): THREE.Texture {
  if (globalTextureCache.has(id)) {
    return globalTextureCache.get(id)!;
  }
  const tex = generateTexture(id);
  globalTextureCache.set(id, tex);
  return tex;
}
```

**后果**: 无缓存时每次创建 2048×1024 Canvas，启动时间增加 2-3 秒，且重复占用显存。

## 4. TypeScript 与代码质量规则

### RULE-TS-001: 所有引擎公共方法必须带 JSDoc

**错误示例**:
```typescript
// ❌ 错误: 无注释
static getDaysSinceJ2000(timestamp: number): number {
  return (timestamp - J2000_TIMESTAMP) / 86400000;
}
```

**正确做法**:
```typescript
/**
 * 计算指定时间戳距离历元 J2000.0 的日子数 (d)
 * @param timestamp UTC 时间戳 (毫秒)
 * @returns 距 J2000.0 的天数，可正可负
 */
static getDaysSinceJ2000(timestamp: number): number {
  return (timestamp - J2000_TIMESTAMP) / 86400000;
}
```

---

### RULE-TS-002: 魔法数字必须注释天文含义

**错误示例**:
```typescript
// ❌ 错误: 13.176396 是什么？
const M = (135 + 13.176396 * days) % 360;
```

**正确做法**:
```typescript
// ✅ 正确: 注释物理含义
const MEAN_MOTION_DEG_PER_DAY = 13.176396; // 月球平均运动速度 (°/天)
const INITIAL_MEAN_ANOMALY = 135; // J2000.0 时刻的初始平均近点角 (°)
const M = (INITIAL_MEAN_ANOMALY + MEAN_MOTION_DEG_PER_DAY * days) % 360;
```

---

### RULE-TS-003: 负数取模必须手动归一化

**错误示例**:
```typescript
// ❌ 错误: JavaScript % 对负数返回负值
const gmst = (18.697 + 24.065 * d) % 24;
// d 为负时，gmst 可能为负值！
```

**正确做法**:
```typescript
// ✅ 正确: 手动归一化到 [0, N)
let gmst = (18.697 + 24.065 * d) % 24;
if (gmst < 0) gmst += 24;
```

**历史案例**: GMST 计算未归一化，导致地面观星时部分恒星位置计算错误。

## 5. UI 与交互规则

### RULE-UI-001: 时间推进必须使用单一 rAF 循环

**错误示例**:
```typescript
// ❌ 错误: setInterval 与 rAF 并存
useEffect(() => {
  requestAnimationFrame(renderLoop);
}, []);

useEffect(() => {
  setInterval(() => { /* 推进时间 */ }, 16);
}, []);
```

**正确做法**:
```typescript
// ✅ 正确: 统一到单一 rAF
useEffect(() => {
  let animId = 0;
  let lastTime = performance.now();
  
  const loop = (now: number) => {
    const deltaSec = (now - lastTime) / 1000;
    lastTime = now;
    
    // 推进时间
    setTimeState(prev => ({
      ...prev,
      currentTimestamp: TimeEngine.tick(prev.currentTimestamp, prev.speedMultiplier, deltaSec)
    }));
    
    animId = requestAnimationFrame(loop);
  };
  
  animId = requestAnimationFrame(loop);
  return () => cancelAnimationFrame(animId);
}, []);
```

**后果**: setInterval 与 rAF 时序竞争导致时间推进不稳定，画面跳帧。

---

### RULE-UI-002: 翻译键必须双语言完备

**错误示例**:
```typescript
// ❌ 错误: 只加了中文，没加英文
const translations = {
  zh: { new_feature: '新功能' },
  en: { /* 忘记添加 */ }
};
```

**正确做法**:
```typescript
// ✅ 正确: 同时添加两种语言
const translations = {
  zh: { new_feature: '新功能' },
  en: { new_feature: 'New Feature' }
};
```

**历史案例**: 多次出现新增功能只有中文翻译，切换英文后显示 `undefined`。

---

### RULE-UI-003: 高流速场景必须考虑缓存失效

**错误示例**:
```typescript
// ❌ 错误: 基于"时间不变则跳过"的缓存
if (timestamp === lastTimestamp) return cachedResult;
// 高流速下 timestamp 每帧都变，缓存命中率 = 0
```

**正确做法**:
```typescript
// ✅ 正确: 量化时间缓存
const quantized = Math.floor(days * 100) / 100;
if (quantized === lastQuantized) return cachedResult;
```

**后果**: 高流速下缓存完全失效，性能反而更差（多了缓存判断开销）。

---

### RULE-DATA-002: 物理参数必须双源交叉验证

**新增天体数据时，必须从至少两个独立来源验证**：
1. NASA Planetary Fact Sheet
2. JPL Horizons
3. IAU 数据

**历史案例**: 水星核心温度写成 900°C，而实际为 1500-2000°C，来源单一且未更新。

## 7. 性能规则

### RULE-PERF-001: 新增功能必须通过性能基线测试

**新增任何渲染效果或计算逻辑前，必须**：
1. 在 Chrome DevTools Performance 面板录制 30 秒
2. 对比新增前后的平均帧率
3. 若帧率下降 > 10%，必须优化或提供开关

---

## 10. 交食演示专属规则

### RULE-ECLIPSE-001: 日食/月食必须共用同一套状态，禁止拆分为独立 phenomenon

**错误示例**:
```typescript
// ❌ 错误: 将日食和月食作为两个独立 phenomenon
const PHENOMENA = [
  { id: 'solar-eclipse', ... },
  { id: 'lunar-eclipse', ... },
];
// 导致状态重复、事件选择器重复、时间轴滑块重复
```

**正确做法**:
```typescript
// ✅ 正确: 统一为 'eclipses'，内部通过 eclipseEventType 区分
const [eclipseEventType, setEclipseEventType] = useState<'solar' | 'lunar' | null>(null);
// 两级选择器（类型 → 事件）在 PhenomenaGuidePanel 内部分支渲染
```

**后果**: 拆分为独立 phenomenon 会导致 `eclipseEventTs`、`eclipseWindow`、`eclipseProgress` 三套状态各写两份，维护成本翻倍，且容易在切换时出现状态不同步。

**历史案例**: 早期文档曾将日食/月食设计为独立 phenomenon（`solar-eclipse` / `lunar-eclipse`），但代码实现时合并为 `eclipses`，导致文档与代码长期不一致。

### RULE-ECLIPSE-002: 阴影锥几何禁止每帧重建

**错误示例**:
```typescript
// ❌ 错误: 每帧 new CylinderGeometry
earthUmbraCone.geometry.dispose();
earthUmbraCone.geometry = new THREE.CylinderGeometry(sectionRadius, earthRadiusScene, coneLen, 48, 1, true);
```

**正确做法**:
```typescript
// ✅ 正确: 使用 userData 缓存尺寸，仅在变化超过阈值时重建
const lastR = aids.earthUmbraCone.userData.lastSectionR || 0;
if (Math.abs(sectionRadius - lastR) > 0.001) {
  aids.earthUmbraCone.geometry.dispose();
  aids.earthUmbraCone.geometry = new THREE.CylinderGeometry(...);
  aids.earthUmbraCone.userData.lastSectionR = sectionRadius;
}
```

**后果**: 每帧重建几何体导致 GPU 显存碎片和频繁 GC，在 1x 流速下帧率下降 20~30%。

**历史案例**: 月食地球截头锥早期未加重建阈值，每帧生成新的 `CylinderGeometry`，Chrome Performance 面板显示 `Geometry.dispose` 和 `new CylinderGeometry` 占用主线程 3~5ms/帧。

### RULE-ECLIPSE-003: 血月颜色过渡必须平滑，禁止直接赋值

**错误示例**:
```typescript
// ❌ 错误: 直接跳变
if (umbralMagnitude >= 1) {
  moonMesh.material.color.setHex(0x8b0000); // 瞬间变红！
}
```

**正确做法**:
```typescript
// ✅ 正确: 每帧 lerp 过渡
const targetColor = umbralMagnitude >= 1 ? new THREE.Color(0x8b0000) : new THREE.Color(0xffffff);
moonMesh.material.color.lerp(targetColor, 0.05); // 5% 每帧过渡
```

**后果**: 直接跳变在视觉上像材质加载 bug，严重影响教学体验。用户会误认为“月球贴图丢失了”。

**历史案例**: 早期血月实现使用条件分支直接 `setHex`，从亮白到暗红的切换仅 1 帧，测试人员多次报 bug。

### RULE-ECLIPSE-004: 半影锥默认隐藏，仅在明确需求时开启

**错误示例**:
```typescript
// ❌ 错误: 同时渲染本影锥和半影锥
moonUmbraCone.visible = true;
moonPenumbraCone.visible = true; // 发散锥在深色背景中形成巨大模糊团
```

**正确做法**:

**后果**: 半影锥是发散的（半顶角 > 0），在宇宙深色背景中占据巨大屏幕空间，遮挡星体和轨道线，且难以与背景区分。

**历史案例**: 日食演示早期渲染了月球半影锥，导致黄道面、地球轨道线被大面积半透明红色遮挡，用户无法看清地月相对位置。

### RULE-ECLIPSE-005: NASA 窗口数据必须做空值回退

**错误示例**:
```typescript
// ❌ 错误: 直接解析，不做 null 检查
const match = event.partialDuration.match(/(\d+)h(\d+)m/);
const hours = parseInt(match[1]); // match 可能为 null！
```

**正确做法**:
```typescript
// ✅ 正确: 空值检查 + 回退策略
if (event.partialDuration) {
  const match = event.partialDuration.match(/(\d+)h(\d+)m/);
  if (match) { /* 使用 NASA 窗口 */ }
  else { /* 回退默认窗口 */ }
} else {
  /* 回退默认窗口 */
}
```

**后果**: 半影月食的 `partialDuration` 为 `null`，直接解析会导致 `TypeError: Cannot read properties of null`，整个交食演示崩溃。

**历史案例**: 2020-01-10 半影月食事件在测试时触发崩溃，因为 `getNASAWindow` 未处理 `partialDuration === null`。

### RULE-ECLIPSE-006: 严格/演示模式切换必须实时响应

**错误示例**:
```typescript
// ❌ 错误: 仅在初始化时读取 strictPhysicsRef
const umbraLen = strictPhysicsRef.current ? earthToMoonDist * 0.98 : earthToMoonDist * 1.02;
// 渲染循环外计算，切换模式后不刷新
```

**正确做法**:
```typescript
// ✅ 正确: 每帧根据当前模式重新计算
const isStrict = strictPhysicsRef.current;
const umbraLen = isStrict ? earthToMoonDist * 0.98 : earthToMoonDist * 1.02;
// 在 requestAnimationFrame 循环内执行
```

**后果**: 用户在演示过程中切换严格/演示模式时，若锥体长度未实时刷新，会造成“按钮点了没反应”的体验问题。

**历史案例**: 早期严格模式切换后，需要等待下一次事件触发（如滑块拖动）才能看到影子锥变化，用户反馈交互延迟。

### RULE-ECLIPSE-007: 交食状态文本必须通过 DOM id 更新，禁止跨组件直接调用

**错误示例**:

```typescript
phenomenaGuidePanelRef.current.setStatusText('日全食');
```

**正确做法**:

```typescript
// ✅ 正确: 通过共享 DOM id 写入（或提升状态到 App.tsx）
const statusTextEl = document.getElementById('eclipse-status-val');
if (statusTextEl) statusTextEl.textContent = '日全食';
```

**后果**: 跨组件直接调用 `ref` 方法会破坏 React 单向数据流，导致状态不可预测，且难以测试。

**历史案例**: 早期尝试通过 `ref` 从 `UniverseViewer` 直接更新 `PhenomenaGuidePanel` 的状态，导致切换现象时旧状态残留，出现“日食状态文本显示在月食界面”的 bug。
