# GalaxySim3D 项目总验证方案

> 版本: v1.0 | 日期: 2026-06-08 | 项目: 梦入银河 (GalaxySim3D)

---

## 1. 验证目标

确保 GalaxySim3D 的所有功能在**科学性、功能性、性能、兼容性**四个维度上达到交付标准。具体目标：

1. **科学性验证**: 所有天文计算结果与权威数据源（NASA JPL Horizons、IAU 标准）的偏差在允许范围内
2. **功能验证**: 所有需求文档中的功能点按预期工作
3. **性能验证**: 1x 流速稳定 60fps，3600x 流速 ≥ 45fps（中端设备）
4. **兼容性验证**: 支持 Chrome/Edge/Firefox/Safari 最新两个主版本

---

## 2. 验证分层策略

验证按项目架构分层进行，确保每层独立可测：

```
L1 引擎层 ──► 单元测试（确定性数学计算）
L2 渲染层 ──► 视觉校验 + 性能测试
L3 UI 层   ──► 功能测试 + 交互测试
L4 应用层  ──► 端到端测试（E2E）
```

**核心原则**: 引擎层（L1）必须 100% 单元测试覆盖，因为上层所有功能都依赖其正确性。

---

## 3. 验证类型

### 3.1 单元测试 (Unit Test)

**范围**: `TimeEngine`, `OrbitEngine`, `AstrophenomenaEngine`, `ObserverEngine`

**方法**: Jest / Vitest，纯数学输入输出验证

**覆盖率要求**: ≥ 90%（核心路径 100%）

### 3.2 集成测试 (Integration Test)

**范围**: 引擎层 → 渲染层的数据流

**方法**: 验证引擎输出正确驱动渲染器显示

**示例**: 给定特定时间戳，验证行星在 3D 场景中的位置与计算值一致

### 3.3 视觉校验 (Visual Regression)

**范围**: 渲染效果、UI 布局、动画过渡

**方法**: Playwright 截图对比 / 人工目视检查

**关键场景**: 
- 地球自转同步（UTC 12:00 本初子午线对准太阳）
- 月相显示正确
- 节气标注正确
- 主题切换无闪烁

### 3.4 性能测试 (Performance Test)

**范围**: 帧率、内存、显存、启动时间

**方法**: Chrome DevTools Performance 面板、Lighthouse

**指标**: 见第 5 节

### 3.5 天文精度校验 (Astronomical Accuracy)

**范围**: 轨道位置、恒星时、月相、节气、交食

**方法**: 与 NASA JPL Horizons、Stellarium、NOAA 数据交叉验证

**允许偏差**:
- 行星位置: ±0.01 AU
- 月球位置: ±0.5°
- 太阳黄经: ±0.1°
- 节气时刻: ±8 小时
- 月相: ±0.5 天

## 6. 验证流程

### 6.1 开发阶段验证

每次代码提交前必须：
1. 运行 `npm run lint`（TypeScript 类型检查）
2. 运行单元测试 `npm test`
3. 手动验证修改的功能点

### 6.2 集成验证

每个里程碑完成后：
1. 全量单元测试
2. 视觉校验关键场景
3. 性能基准测试
4. 跨浏览器兼容性抽查

### 6.3 发布验证

每个版本发布前：
1. 全量单元测试 + 覆盖率报告
2. 全浏览器矩阵测试
3. 全分辨率矩阵测试
4. 天文精度交叉验证（抽样）
5. 性能基准测试
6. 无障碍性检查（键盘导航、屏幕阅读器）

## 8. 已知风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 月球精度难以验证 | 月食演示偏差 | 使用 Stellarium 作为交叉验证工具 |
| 视觉校验主观性强 | 漏检渲染 bug | 建立标准截图库，Playwright 自动对比 |
| 性能基准波动 | 误判性能退化 | 同一设备上跑 3 次取中位数 |
| 浏览器兼容性差异 | 部分功能不可用 | 建立 graceful degradation 策略 |
