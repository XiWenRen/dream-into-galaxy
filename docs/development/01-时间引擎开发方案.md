# 时间引擎开发方案 (TimeEngine)

> 版本: v1.0 | 日期: 2026-06-08 | 模块: TimeEngine (L1 引擎层)

---

## 1. 目标

1. 实现 UTC 时间戳与天文历元 (J2000.0) 的精确换算
2. 提供多种天文时间尺度（TT、TDB、UT1）的转换接口
3. 实现本地恒星时计算，为地面观星提供时角基准
4. 实现时间递增驱动，支持任意倍速的时间流逝
5. 所有方法为纯函数，无外部依赖，便于单元测试

---

## 2. 技术选型

### 2.1 选型: 纯 TypeScript 类，无外部依赖

**原因**：
1. 时间换算为纯数学运算，无需 Three.js 或 DOM API
2. 无依赖意味着可独立测试、独立复用
3. 计算量极小（几次加减乘除），不需要 Web Worker
4. 可作为 npm 包独立发布的天文时间库

### 2.2 选型: Meeus 简化 ΔT 公式

**原因**：
1. 教育场景下 ±5 秒的 TT-UTC 差值精度完全足够
2. 无需接入 IERS 的 ΔT 数据服务（增加网络依赖）
3. 公式覆盖 2000-2100 年，满足项目生命周期

**未选精确 ΔT 表的原因**：
- IERS 发布的 ΔT 表需要定期更新和网络请求
- 浏览器环境下难以保证实时数据可用性

### 2.3 选型: GMST 简化公式 (18.697374558 + 24.06570982441908 × d)

**原因**：
1. 该公式精度约 ±0.1 秒，满足肉眼观星需求
2. 比 IAU 2000 规范公式简单得多，无矩阵运算
3. 教育场景不需要毫角秒级精度

**未选 IAU 2000 GMST 公式的原因**：
- IAU 2000 公式包含数十项修正，代码量大
- 精度提升（从 ±0.1秒到 ±1微秒）对教育场景无意义

## 3. 实现步骤

### Step 1: 定义常量

```typescript
export const J2000_TIMESTAMP = 946728000000; // 2000-01-01T12:00:00Z
const MS_PER_DAY = 86400000;
```

**关键点**: 使用毫秒时间戳而非秒，与 JavaScript Date 保持一致。

### Step 2: 实现基础换算

```typescript
static getDaysSinceJ2000(timestamp: number): number {
  return (timestamp - J2000_TIMESTAMP) / MS_PER_DAY;
}
```

**验证**: `getDaysSinceJ2000(J2000_TIMESTAMP)` 必须返回 0。

### Step 3: 实现时间尺度转换

```typescript
static getDeltaT(timestamp: number): number {
  const year = new Date(timestamp).getUTCFullYear();
  return 64.3 + 0.5 * (year - 2000); // 秒
}

static getTT(timestamp: number): number {
  return timestamp + this.getDeltaT(timestamp) * 1000;
}

static getTDB(timestamp: number): number {
  return this.getTT(timestamp); // 浏览器级精度下近似
}

static getUT1(timestamp: number): number {
  return timestamp; // 无 EOP 数据时最佳近似
}
```

**注意**: `getUT1` 返回 UTC 作为近似值。真实 UT1 与 UTC 的差异（DUT1）通常在 ±0.5 秒内，对恒星时计算影响约 ±7.5 角秒，肉眼不可见。

### Step 4: 实现恒星时计算

```typescript
static getLocalSiderealTime(timestamp: number, longitude: number): number {
  const d = this.getDaysSinceJ2000UT1(timestamp);
  let gmst = (18.697374558 + 24.06570982441908 * d) % 24;
  if (gmst < 0) gmst += 24;
  let lst = gmst + longitude / 15;
  lst = lst % 24;
  if (lst < 0) lst += 24;
  return lst;
}
```

**关键点**:
- GMST 基于 UT1 而非 UTC 或 TT
- 结果对 24 取模并归一化到 [0, 24)
- 经度东为正，西为负

### Step 5: 实现 tick 递增

```typescript
static tick(currentTimestamp: number, speedMultiplier: number, deltaTimeSeconds: number): number {
  return currentTimestamp + speedMultiplier * deltaTimeSeconds * 1000;
}
```

**设计决策**: 
- `deltaTimeSeconds` 来自 `requestAnimationFrame` 的实际时间差，而非固定 1/60 秒
- 这样可以兼容不同刷新率显示器和掉帧情况

### Step 6: 实现辅助工具

```typescript
static getTimestampForLocalHour(dateTimestamp: number, localHour: number, timezoneOffset: number): number {
  const localMs = dateTimestamp + timezoneOffset * 3600 * 1000;
  const localDate = new Date(localMs);
  const year = localDate.getUTCFullYear();
  const month = localDate.getUTCMonth();
  const date = localDate.getUTCDate();
  const hour = Math.floor(localHour);
  const minutes = Math.round((localHour - hour) * 60);
  const targetLocalMs = Date.UTC(year, month, date, hour, minutes, 0, 0);
  return targetLocalMs - timezoneOffset * 3600 * 1000;
}
```

**用途**: 天文演示中需要跳转到"某一天的晚上 8 点"，此函数将本地时间转换为 UTC 时间戳。

## 4. 预期结果

### 4.1 单元测试结果

| 测试用例 | 输入 | 预期输出 |
|----------|------|----------|
| J2000 历元 | `946728000000` | `0` 天 |
| 一天后 | `946728000000 + 86400000` | `1.0` 天 |
| ΔT 2000年 | `946728000000` | `64.3` 秒 |
| ΔT 2020年 | `1577836800000` | `74.3` 秒 |
| GMST 已知值 | 对比天文年历 | 误差 < 0.01h |
| tick 1x | speed=1, delta=1 | +1000ms |
| tick 86400x | speed=86400, delta=1 | +86400000ms (1天) |

### 4.2 集成验证

1. 连续运行 24 小时模拟时间，恒星时增量应为 `24.0657h` 而非 `24h`
2. 北京（东经 121.47°）的 LST 应比格林尼治大 `121.47/15 ≈ 8.1` 小时

## 5. 踩坑记录

1. **UT1 vs UTC 混淆**: 早期版本使用 UTC 计算 GMST，导致恒星时每天累积约 1 秒误差。修正后使用 UT1（近似为 UTC）。
2. **负数取模**: JavaScript `%` 对负数返回负值，必须手动归一化：`if (gmst < 0) gmst += 24`
3. **getUTCFullYear 陷阱**: `new Date(timestamp).getUTCFullYear()` 与 `new Date(timestamp).getFullYear()` 在不同时区机器上结果不同，必须使用 UTC 方法
