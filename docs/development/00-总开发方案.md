# GalaxySim3D 项目总开发方案

> 版本: v1.0 | 日期: 2026-06-08 | 项目: 梦入银河 (GalaxySim3D)

---

## 1. 项目目标

构建一个面向青少年的 3D Web 太阳系-银河系教学系统，核心交付物包括：
1. **科学可信的轨道计算引擎**：基于 J2000.0 历元，行星位置精度 ±0.01 AU，月球位置精度 ±0.5°
2. **双模式渲染系统**：宇宙视角（太空漫游）与地面观星（天球投影）无缝切换
3. **天文现象演示系统**：月相、交食、24 节气的分步交互演示
4. **高保真视觉效果**：8K 贴图、大气散射、光照阴影、剖面模式
5. **教育级 UI 系统**：驾驶舱风格、国际化、主题切换

## 2. 技术选型

### 2.1 前端框架

**选型: React 19 + TypeScript**

**原因**：
1. React 19 的并发特性和自动批处理能提升高频状态更新（时间推进、动画帧）的性能
2. TypeScript 提供严格的类型检查，对天文计算这种强数学逻辑的项目至关重要
3. 组件化架构天然适配分层设计（引擎层、渲染层、UI 层）
4. 生态丰富，Three.js 的 React 集成（@react-three/fiber 备选）成熟

**未选 Vue/Angular 的原因**：
- Vue 的响应式系统对高频数值更新（每帧 60 次）有一定 overhead
- Angular 体积较大，对加载速度敏感的教育场景不够轻量

### 2.2 3D 渲染引擎

**选型: Three.js (原生，非 R3F)**

**原因**：
1. Three.js 是 WebGL 的事实标准封装，文档完善，社区活跃
2. 本项目需要深度自定义 Shader（大气散射、云层、剖面裁剪），原生 Three.js 更灵活
3. @react-three/fiber 的声明式抽象对高频 imperative 更新（如每帧修改 BufferGeometry）不够高效
4. 双 Viewer（UniverseViewer + StarrySkyViewer）需要精细控制渲染循环，原生 API 更合适

**未选 Babylon.js 的原因**：
- Babylon.js 更偏向游戏开发，天文模拟所需的功能（Points、LineSegments、Sprite）Three.js 同样完善
- Three.js 包体积更小，对网页加载更友好

### 2.3 构建工具

**选型: Vite**

**原因**：
1. 开发服务器冷启动极快（秒级），对大型项目体验好
2. 原生 ESM 支持，与现代浏览器配合无需大量 polyfill
3. HMR 速度快，修改 Shader 代码后即时生效
4. 生产构建使用 esbuild/rollup，输出体积小

### 2.4 样式方案

**选型: Tailwind CSS v4**

**原因**：
1. 原子化 CSS 与组件化开发天然契合
2. 主题系统通过 CSS 变量实现，切换主题只需修改变量值
3. v4 版本性能大幅提升，无需 purgecss 配置
4. 与 Vite 集成简单（@tailwindcss/vite 插件）

### 2.5 动画库

**选型: Framer Motion (仅用于 UI 动画)**

**原因**：
1. React 组件动画（面板滑入、按钮缩放）使用 Framer Motion 声明式实现最简洁
2. 3D 场景动画（相机移动、行星公转）使用 Three.js 的 requestAnimationFrame 循环，无需额外动画库
3. 明确边界：Framer Motion 只管 DOM 动画，不管 Canvas 动画

### 2.6 状态管理

**选型: React 原生 useState/useRef（当前阶段）**

**原因**：
1. 当前状态复杂度可控，App.tsx 集中管理即可
2. 引入 Redux/Zustand 会增加学习成本和包体积
3. 未来若状态复杂度增长，可平滑迁移至 Zustand

## 3. 架构设计

### 3.1 五层架构

```
L4: 应用层 (Application)
 ├── App.tsx (状态中心、路由壳)
 ├── i18n (国际化字典)
 └── 主题系统

L3: UI 层 (Presentation)
 ├── CommandPanel (控制面板)
 ├── PlanetInfoPanel (行星信息面板)
 ├── ArcTimeBar (时间控制条)
 ├── AstroPhenomenaPanel (天象面板)
 └── PhenomenaDemoBar (演示控制条)

L2: 渲染层 (Rendering)
 ├── UniverseViewer (宇宙视角)
 ├── StarrySkyViewer (地面观星)
 ├── TelescopeOverlay (望远镜遮罩)
 └── TransitionScreen (过渡动画)

L1: 引擎层 (Simulation)
 ├── TimeEngine (时间引擎)
 ├── OrbitEngine (轨道引擎)
 ├── AstrophenomenaEngine (天象引擎)
 └── ObserverEngine (观星引擎)

L0: 数据层 (Data Foundation)
 ├── 轨道根数常量 (PLANET_ORBITAL_DATA)
 ├── 星表数据库 (StarDatabase / Hipparcos)
 ├── 行星物理参数 (CELESTIAL_PHYSICS)
 └── 纹理/材质资源 (public/textures/)
```

### 3.2 核心依赖规则

```
L4 依赖: L3, L2, L1, L0
L3 依赖: L1 (读取引擎结果)
L2 依赖: L1 (获取坐标/角度), L0 (获取贴图/星表)
L1 依赖: L0 (读取常量数据)
L0 不依赖任何上层

禁止:
- 同层横向依赖（如 UniverseViewer 直接调用 StarrySkyViewer 方法）
- 下层依赖上层（如 OrbitEngine 引用 Three.js）
- 引擎层引用 React hooks
```

### 3.3 数据流设计

```
用户交互 → App.tsx 状态更新
                │
                ├──► TimeEngine.tick() → 新时间戳
                ├──► OrbitEngine.getHeliocentricPosition() → 行星坐标
                ├──► OrbitEngine.getRotationAngle() → 自转角度
                ├──► AstrophenomenaEngine.getCurrentSolarTerm() → 节气
                ├──► AstrophenomenaEngine.getMoonPhase() → 月相
                ├──► ObserverEngine.getSolarRADec() → 太阳天球坐标
                └──► TimeEngine.getLocalSiderealTime() → LST
                │
                ▼
        渲染分发 (由 landed 状态决定)
        landed=false → UniverseViewer (日心坐标 + 自转)
        landed=true  → StarrySkyViewer (水平坐标 + 天球投影)
```

## 4. 开发里程碑

### 4.1 M0: 基础引擎验证期 (已完成)

- [x] TimeEngine: J2000 换算、恒星时计算

- [x] NASA Horizons 校验方法

**交付标准**: 引擎单元测试全部通过

### 4.2 M1: 双模式渲染引擎期 (已完成)

- [x] UniverseViewer: 太阳系渲染、轨道线、卫星系统
- [x] StarrySkyViewer: 天球星图、日月投影、星座连线
- [x] 无极缩放过渡动画
- [x] 高清贴图系统: 8K 行星贴图

**交付标准**: 两套渲染器可独立运行并通过视觉校验

### 4.3 M2: 物理真实感与多层渲染期 (已完成)

- [x] 自转角度精确同步（UTC 校验）

**交付标准**: 地球自转角度经 UTC 校验正确；剖面模式可展示岩质行星

### 4.4 M3: 天文现象与交互 UI 期 (已完成)

- [x] 天文现象模拟: 日食/月食可视化、24 节气标注、月相实时展示

- [x] 驾驶舱风格 UI
- [x] 时间节点预设

**交付标准**: UI 交互流畅，天文现象模拟与引擎计算结果一致

### 4.5 M4: 性能优化与架构完善期 (进行中)

- [ ] 合并双 WebGL 上下文

## 6. 编码规范

### 6.1 命名规范

| 层级 | 类/接口 | 方法 | 常量 |
|------|---------|------|------|
| 引擎 | PascalCase | camelCase | UPPER_SNAKE_CASE |
| 组件 | PascalCase | camelCase | camelCase |
| 类型 | PascalCase | - | - |

### 6.2 注释规范

- 所有引擎公共方法必须带 JSDoc 注释
- 复杂天文算法必须注释物理意义和公式来源
- 魔法数字必须解释其天文含义

### 6.3 提交规范

```
feat: 新功能
fix: 修复
test: 单元测试
docs: 文档更新
refactor: 重构（不改变行为）
perf: 性能优化
```

## 7. 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 月球精度不足 | 月食演示偏差 1~2 天 | 引入 Meeus 摄动修正 + NASA 数据查表 |
| 性能瓶颈（恒星计算） | 高流速卡顿 | Phase 3 Shader 化迁移 |
| 双 WebGL 上下文崩溃 | 移动端无法运行 | Phase 2 合并为单一上下文 |
| 贴图加载慢 | 首屏等待时间长 | LOD 加载 + TextureFactory 缓存 |
| 科学数据错误 | 教育可信度下降 | 建立 NASA 数据校验流水线 |
