# 天文现象引擎开发方案 (AstrophenomenaEngine)

> 版本: v1.0 | 日期: 2026-06-08 | 模块: AstrophenomenaEngine (L1 引擎层)

---

## 1. 目标

1. 基于轨道引擎输出计算太阳黄经，进而确定 24 节气
2. 计算月相（8 个阶段）和精确的新月/满月时间
3. 检测日食和月食的发生条件、类型、食分
4. 集成 NASA 权威交食数据，支持事件搜索和描述
5. 为天文演示系统提供时间定位和相位计算支持

---

## 2. 技术选型

### 2.1 选型: 基于简化轨道模型的天象计算

**原因**：
1. 太阳黄经直接由地球平均黄经推导，无需额外计算
2. 月相基于日-地-月夹角，使用轨道引擎输出的坐标即可
3. 精度足够：节气误差 ±8 小时，月相误差 ±0.5 天

### 2.2 选型: 迭代搜索定位精确月相时间

**原因**：
1. 月相的精确时刻无法解析求解，需数值搜索
2. 使用逐步缩小步长的梯度下降法，4 轮迭代可达分钟级精度
3. 计算量小（每轮 11 个采样点 × 4 轮 = 44 次轨道计算）

### 2.3 选型: 预置 NASA 交食事件表

**原因**：
1. 交食检测的简化模型只能判断"是否可能发生"，无法精确预测食带
2. NASA 数据提供权威的时间、类型、食分、可见区域
3. 数据量可控（2015-2035 年约 200 个事件，~30KB JSON）

**未选实时计算作为唯一来源的原因**：
- 精确交食预测需要完整的贝塞尔根数计算，代码复杂
- 教育场景下使用权威数据更可信

## 3. 实现步骤

### Step 1: 实现太阳黄经计算

```typescript
static getSolarLongitude(days: number): number {
  const earthPos = OrbitEngine.getHeliocentricPosition('earth', days);
  let lon = (Math.atan2(earthPos.y, earthPos.x) * 180 / Math.PI - 180) % 360;
  if (lon < 0) lon += 360;
  return lon;
}
```

**关键点**: 太阳黄经 = 地球黄经 - 180°（日心坐标相反方向）。

### Step 2: 实现节气判定

```typescript
static getCurrentSolarTerm(days: number) {
  const lon = this.getSolarLongitude(days);
  const index = Math.floor(lon / 15) % 24;
  const nextIndex = (index + 1) % 24;
  return {
    current: SOLAR_TERMS_LIST[index],
    next: SOLAR_TERMS_LIST[nextIndex],
    currentLong: lon
  };
}
```

**边界处理**: 当 lon 接近 360° 时，nextIndex 应回到 0（春分）。

### Step 3: 实现月相计算

```typescript
static getMoonPhase(days: number) {
  const earthPos = OrbitEngine.getHeliocentricPosition('earth', days);
  const moonRel = OrbitEngine.getLunarRelativePosition(days);
  
  // 计算日-地-月夹角（黄道面投影）
  const es = { x: -earthPos.x, y: -earthPos.y };
  const em = { x: moonRel.x, y: moonRel.y };
  
  const angle = Math.atan2(
    es.x * em.y - es.y * em.x,
    es.x * em.x + es.y * em.y
  );
  
  let phaseAngle = angle;
  if (phaseAngle < 0) phaseAngle += 2 * Math.PI;
  
  const phaseIndex = Math.round(phaseAngle / (2 * Math.PI) * 8) % 8;
  const percent = 0.5 * (1 - Math.cos(phaseAngle));
  
  return { phaseIndex, nameKey: PHASE_NAMES[phaseIndex], percent };
}
```

**关键点**: 使用 `atan2` 计算有符号夹角，确保方向正确（峨眉月 vs 残月）。

### Step 4: 实现精确新月定位

```typescript
export function getCurrentCycleNewMoon(referenceTimestamp: number): number {
  const knownNewMoon = Date.UTC(2000, 0, 16, 22, 59, 0); // 已知新月
  const monthsSince = (referenceTimestamp - knownNewMoon) / SYNODIC_MONTH_MS;
  let baseTs = knownNewMoon + Math.floor(monthsSince) * SYNODIC_MONTH_MS;
  
  // 迭代精化
  let step = 24 * 3600 * 1000; // 1 天
  for (let iter = 0; iter < 4; iter++) {
    let bestTs = baseTs;
    let minAngle = Infinity;
    for (let offset = -5; offset <= 5; offset++) {
      const ts = baseTs + offset * step;
      const days = (ts - 946728000000) / 86400000;
      const earthPos = OrbitEngine.getHeliocentricPosition('earth', days);
      const moonRel = OrbitEngine.getLunarRelativePosition(days);
      
      // 计算日-地-月夹角
      const es = { x: -earthPos.x, y: -earthPos.y, z: -earthPos.z };
      const dot = es.x * moonRel.x + es.y * moonRel.y + es.z * moonRel.z;
      const cosAngle = dot / (len(es) * len(moonRel));
      const angle = Math.acos(Math.max(-1, Math.min(1, cosAngle)));
      
      if (angle < minAngle) {
        minAngle = angle;
        bestTs = ts;
      }
    }
    baseTs = bestTs;
    step /= 5;
  }
  return baseTs;
}
```

**收敛性**: 4 轮迭代后步长缩小到 `1/5⁴ = 1/625` 天 ≈ 2.3 分钟。

### Step 5: 实现交食检测

```typescript
static detectEclipse(days: number) {
  const earthPos = OrbitEngine.getHeliocentricPosition('earth', days);
  const moonRel = OrbitEngine.getLunarRelativePosition(days);
  
  // 日-地-月夹角
  const es = { x: -earthPos.x, y: -earthPos.y, z: -earthPos.z };
  const em = moonRel;
  const dot = es.x * em.x + es.y * em.y + es.z * em.z;
  const esLen = Math.sqrt(es.x**2 + es.y**2 + es.z**2);
  const emLen = Math.sqrt(em.x**2 + em.y**2 + em.z**2);
  const angle = Math.acos(Math.max(-1, Math.min(1, dot / (esLen * emLen))));
  
  // 视角半径（度）
  const sunAngularRadius = 0.2666 / esLen; // 太阳视角半径 ≈ 0.2666°/AU
  const moonAngularRadius = 0.259 / emLen; // 月球视角半径 ≈ 0.259°/AU
  
  // 日食检测
  const solarEclipse = angle < (sunAngularRadius + moonAngularRadius);
  
  // 月食检测（简化）
  const earthShadowRadius = 0.72; // 地球本影在月球距离处的视角半径
  const lunarEclipse = Math.abs(angle - 180) < (earthShadowRadius + moonAngularRadius);
  
  return { solarEclipse, lunarEclipse, angleDegrees: angle * 180 / Math.PI };
}
```

**局限性**: 此简化检测只能判断"是否可能发生交食"，无法判断类型（全食/环食/偏食）和可见区域。

### Step 6: 集成 NASA 交食数据

```typescript
static searchEclipseEvents(centerTimestamp: number, windowYears = 10) {
  const centerDate = new Date(centerTimestamp);
  const startYear = centerDate.getFullYear() - windowYears;
  const endYear = centerDate.getFullYear() + windowYears;
  
  const events: EclipseEvent[] = [];
  for (const se of SOLAR_ECLIPSE_EVENTS) {
    const year = parseInt(se.date.split('-')[0]);
    if (year >= startYear && year <= endYear) {
      events.push({
        timestamp: new Date(`${se.date}T${se.greatestUTC}Z`).getTime(),
        type: 'solar',
        dateStr: se.date,
        detail: se
      });
    }
  }
  // 月食同理...
  return events.sort((a, b) => a.timestamp - b.timestamp);
}
```

## 5. 踩坑记录

1. **月相方向错误**: 早期使用无符号夹角计算，导致峨眉月和残月无法区分。修正为使用 `atan2` 计算有符号角。
2. **节气索引越界**: 太阳黄经接近 360° 时，`floor(lon/15)` 返回 24，数组越界。修正为 `% 24`。
3. **新月搜索发散**: 步长缩小系数原为 2，收敛慢。改为 5 后，4 轮即可达分钟级精度。
4. **交食 false positive**: 简化模型在日-地-月夹角较小时即报告日食，未考虑月球是否在黄道面附近。已标注为"演示级检测"。
5. **朔望月 vs 恒星月混淆**: 科普文本中曾将 27.3 天和 29.5 天混为一谈，导致月相周期描述错误。
