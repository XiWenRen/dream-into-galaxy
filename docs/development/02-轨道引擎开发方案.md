# 轨道引擎开发方案 (OrbitEngine)

> 版本: v1.0 | 日期: 2026-06-08 | 模块: OrbitEngine (L1 引擎层)

---

## 1. 目标

1. 实现基于克卜勒轨道根数的行星日心坐标计算
2. 实现月球相对地球的精确位置计算（含 Meeus 摄动修正）
3. 实现各天体自转角度计算（与 UTC 时间同步）
4. 实现 NASA Horizons LUT 校准系统
5. 实现天然卫星的简化轨道计算
6. 所有方法为纯函数，支持独立单元测试

---

## 2. 技术选型

### 2.1 选型: 简化克卜勒模型 + 线性变率

**原因**：
1. 教育场景不需要 VSOP87 级数的数十项修正
2. 线性变率模型在 100 年内精度约 ±0.01 AU，足够演示
3. 计算速度快，每行星仅需 1 次迭代求解克卜勒方程

**未选 VSOP87/DE440 的原因**：
- VSOP87 包含数百项三角级数，代码量巨大（~5000 行）
- DE440 需要数 MB 的 Chebyshev 系数表，网络加载慢
- 精度提升（从 ±0.01AU 到 ±1e-6AU）对教育场景无意义

### 2.2 选型: Newton-Raphson 迭代求解克卜勒方程

**原因**：
1. 5 次迭代后误差 < 1e-12 弧度，远超天文需求
2. 实现简单，仅需基本三角函数
3. 比二分法收敛更快（二次收敛）

### 2.3 选型: Meeus 低精度月球模型（20 项修正）

**原因**：
1. 将月球精度从 ±2° 提升到 ±0.5°，满足月食演示
2. 仅 20 项三角函数，计算开销小
3. 纯代码实现，无外部数据依赖

**未选 ELP-2000 的原因**：
- ELP-2000 含 ~1000 项系数，代码量 ~100KB
- ±0.001° 的精度对教育场景是过度设计

### 2.4 选型: 预计算 LUT 校准表

**原因**：
1. 修正简化模型与 NASA Horizons 的系统性偏差
2. 数据量小（2018-2028 年，9 天体，10 天间隔，约 50KB）
3. 运行时仅需双线性插值，开销极小

## 3. 实现步骤

### Step 1: 定义轨道根数数据

```typescript
export interface KeplerElements {
  id: string;
  a: number;       // 半长轴 AU
  e: number;       // 偏心率
  I: number;       // 倾角度
  L: number;       // 平均黄经 J2000
  longPeri: number; // 近日点黄经
  node: number;    // 升交点黄经
  period: number;  // 公转周期 天
  dL?: number;     // 变率 deg/cy
  dLongPeri?: number;
  dNode?: number;
  dE?: number;
  dI?: number;
}
```

**数据来源**: NASA JPL Horizons + Meeus《天文算法》表 30.A

### Step 2: 实现轨道根数传播

```typescript
const T = days / 36525.0; // 儒略世纪数

let L = elem.L;
let longPeri = elem.longPeri;
let node = elem.node;
let e = elem.e;
let I = elem.I;

if (elem.dL !== undefined) {
  L += elem.dL * T;
  longPeri += (elem.dLongPeri ?? 0) * T;
  node += (elem.dNode ?? 0) * T;
  e += (elem.dE ?? 0) * T;
  I += (elem.dI ?? 0) * T;
}
```

**关键点**: 只有包含变率（dL 等）的行星才进行传播。若缺失变率，回退到固定周期模型。

### Step 3: 实现克卜勒方程求解

```typescript
let M: number;
if (elem.dL !== undefined) {
  M = (L - longPeri) % 360;
} else {
  const n = 360.0 / elem.period;
  M = (elem.L - elem.longPeri + n * days) % 360;
}
if (M < 0) M += 360;
const mRad = (M * Math.PI) / 180.0;

// Newton-Raphson 迭代
let E = mRad;
for (let count = 0; count < 5; count++) {
  const deltaE = (E - e * Math.sin(E) - mRad) / (1.0 - e * Math.cos(E));
  E -= deltaE;
}
```

**收敛保证**: 偏心率 e < 0.25 时，Newton-Raphson 从 E₀=M 开始必然收敛。

### Step 7: 实现自转角度计算

```typescript
static getRotationAngle(id: string, timestamp: number): number {
  const phys = CELESTIAL_PHYSICS[id];
  if (!phys) return 0;
  
  const hoursSinceJ2000 = (timestamp - J2000_TIMESTAMP) / 3600000;
  const rotationCycles = hoursSinceJ2000 / phys.rotationPeriod;
  let angle = (rotationCycles * 2 * Math.PI) % (2 * Math.PI);
  
  // 逆向自转
  if (phys.rotationPeriod < 0) {
    angle = -angle;
  }
  
  // 贴图校准偏移 + 本初子午线偏移
  angle += phys.primeMeridianOffsetRad;
  
  return angle;
}
```

**关键点**: 
- 使用 UT1 时间（近似为 UTC）而非 TT
- 地球贴图需额外叠加 `-Math.PI / 2` 校准偏移

### Step 8: 实现轨道可视化函数

```typescript
static getLunarOrbitPoints(days: number, samples: number): {x, y, z}[] {
  // 固定使用当前历元的根数
  const moonA = 0.00257;
  const e = 0.0549;
  const iRad = (5.145 * Math.PI) / 180.0;
  const periDeg = (318.15 + 0.1114 * days) % 360;
  const nodeDeg = (125.08 - 0.05295 * days) % 360;
  
  // 遍历真近点角 0~2π，绘制闭合椭圆
  const points = [];
  for (let k = 0; k <= samples; k++) {
    const f = (k / samples) * 2 * Math.PI;
    const r = moonA * (1 - e * e) / (1 + e * Math.cos(f));
    // 旋转到黄道坐标...
    points.push({x, y, z});
  }
  return points;
}
```

**与真实位置的区别**: 此函数用于可视化，使用固定根数绘制闭合椭圆；`getLunarRelativePosition()` 用于物理计算，使用瞬时根数。

## 5. 踩坑记录

1. **月球轨道未闭合**: 早期使用 `getLunarRelativePosition()` 逐点绘制轨道，因根数随时间变化导致首尾间隙。修正为 `getLunarOrbitPoints()` 使用固定根数绘制闭合椭圆。
2. **近日点幅角 vs 近日点黄经**: 曾混淆 `longPeri` 和 `omega`，导致轨道平面方向错误。`omega = longPeri - node`。
3. **自转方向符号**: 金星和天王星的 rotationPeriod 为负值，表示逆向自转。未正确处理导致贴图反向旋转。
4. **地球贴图偏移**: 未叠加 `-Math.PI/2` 校准偏移，导致 UTC 12:00 时本初子午线未对准太阳。
5. **LUT 索引越界**: 超出 2018-2028 范围时未做边界保护，导致插值异常。
