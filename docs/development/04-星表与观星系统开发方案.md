# 星表与观星系统开发方案 (StarDatabase / ObserverEngine)

> 版本: v1.0 | 日期: 2026-06-08 | 模块: StarDatabase / ObserverEngine (L0/L1 引擎层)

---

## 1. 目标

1. 建立完整的恒星数据库（Hipparcos 星表 + 42 颗亮星详细信息）
2. 实现岁差修正（IAU 2006）、章动计算（IAU 1980）
3. 实现黄道-赤道-水平坐标系转换链路
4. 实现大气消光模型
5. 支持多参考系观测（从任意太阳系天体表面观星）

---

## 2. 技术选型

### 2.1 选型: Hipparcos 星表 JSON 文件

**原因**：
1. 亮星子集（mag ≤ 6.5）约 8,785 颗，JSON 文件约 800KB，gzip 后 ~200KB
2. 浏览器可快速解析，无需服务器数据库
3. 字段精简：只保留位置、星等、色指数、自行

**未选数据库/API 的原因**：
- 本地 JSON 加载快于网络 API（无延迟）
- 离线场景（教室网络不稳定）可用

### 2.2 选型: IAU 2006 简化岁差 + IAU 1980 简化章动

**原因**：
1. IAU 2006 完整岁差矩阵含高阶项，教育场景不需要
2. 简化模型精度约 ±1 角秒，远超肉眼极限（±1 角分）
3. 代码量小，计算快

### 2.3 选型: CPU 端坐标转换（当前）→ GPU Shader 化（未来）

**原因（当前 CPU 方案）**：
1. 开发快速，易于调试
2. 与 Three.js Points 系统集成简单

**迁移方向（GPU Shader）**：
1. 将 8785 颗星的 J2000 坐标一次性上传为 BufferGeometry attribute
2. 在顶点着色器中执行岁差矩阵 × 赤道转水平
3. 每帧只需更新 4~6 个 uniform（yearsSinceJ2000, LST, lat, magLimit）
4. 从 ~35 万次三角函数/帧（CPU）降至 ~0.1ms（GPU）

### Step 3: 章动计算实现

```typescript
static getNutationAngles(days: number) {
  const T = days / 36525.0;
  const D2R = Math.PI / 180.0;
  
  const Omega = (125.04452 - 1934.136261 * T) * D2R;
  const L = (280.4665 + 36000.7698 * T) * D2R;
  const Lp = (218.3165 + 481267.8813 * T) * D2R;
  
  const deltaPsiArcsec =
    -17.20 * Math.sin(Omega)
    - 1.32 * Math.sin(2 * L)
    - 0.23 * Math.sin(2 * Lp)
    + 0.21 * Math.sin(2 * Omega);
  
  const deltaEpsilonArcsec =
    +9.20 * Math.cos(Omega)
    + 0.57 * Math.cos(2 * L)
    + 0.10 * Math.cos(2 * Lp)
    - 0.09 * Math.cos(2 * Omega);
  
  return {
    deltaPsiRad: deltaPsiArcsec * D2R / 3600.0,
    deltaEpsilonRad: deltaEpsilonArcsec * D2R / 3600.0
  };
}
```

### Step 4: 赤道转水平坐标

```typescript
static getHorizontalCoordinates(ra: number, dec: number, lst: number, lat: number) {
  const ha = (lst - ra) * 15 * Math.PI / 180; // 时角转弧度
  const decRad = dec * Math.PI / 180;
  const latRad = lat * Math.PI / 180;
  
  const sinAlt = Math.sin(decRad) * Math.sin(latRad) + 
                 Math.cos(decRad) * Math.cos(latRad) * Math.cos(ha);
  const alt = Math.asin(sinAlt);
  
  const cosAz = (Math.sin(decRad) - Math.sin(alt) * Math.sin(latRad)) / 
                (Math.cos(alt) * Math.cos(latRad));
  let az = Math.acos(Math.max(-1, Math.min(1, cosAz)));
  
  // 东/西半球修正
  if (Math.sin(ha) > 0) az = 2 * Math.PI - az;
  
  return { az: az * 180 / Math.PI, alt: alt * 180 / Math.PI };
}
```

**关键点**: 方位角从南点起算（天文惯例）还是从北点起算（导航惯例），需与 UI 标注一致。

### Step 5: 大气消光实现

```typescript
static getAtmosphericExtinction(mag: number, altDeg: number) {
  if (altDeg <= 0) return Infinity; // 地平线以下不可见
  const k = 0.2; // 消光系数
  const X = 1 / Math.sin(altDeg * Math.PI / 180); // 大气质量
  return mag + k * X;
}
```

### Step 6: 多参考系观测

```typescript
static getSolarRADec(ctx: ObserverContext, days: number) {
  const observerPos = OrbitEngine.getHeliocentricPosition(ctx.bodyId, days);
  // 太阳方向 = -观测者位置
  const eq = this.eclipticToEquatorial(-observerPos.x, -observerPos.y, -observerPos.z, days);
  return this.vectorToRADec(eq.x, eq.y, eq.z);
}
```

**通用模式**: 从 A 天体看 B 天体 = B 的日心坐标 - A 的日心坐标，再转赤道坐标。

## 5. 踩坑记录

1. **岁差方向错误**: 早期将岁差矩阵应用于当前历元→J2000.0 方向，与需求相反。应为 J2000.0 → 当前历元。
2. **章动符号错误**: Δψ 和 Δε 的符号曾混淆，导致恒星坐标系统性偏移。
3. **方位角基准不一致**: 天文计算从南点起算，UI 标注从北点起算，导致东/西方向标注错误。
4. **恒星时忽略经度**: 早期 LST 计算未加入经度修正，导致所有地点的星空相同。
5. **Hipparcos 赤经单位**: 原始数据为角度，误当作小时使用，导致恒星位置偏移 15 倍。
